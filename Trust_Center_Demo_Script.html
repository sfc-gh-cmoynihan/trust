1.1 Open Trust Center Dashboard

[Navigate to Snowsight: Monitoring > Trust Center]

Point out on screen:

  • Severity badges at the top -- Critical, High, Medium, Low counts

1.2 Show Findings Summary

[Switch to SQL worksheet]

SELECT SEVERITY,
       COUNT(DISTINCT SCANNER_NAME) AS SCANNERS_WITH_FINDINGS,
       SUM(TOTAL_AT_RISK_COUNT) AS TOTAL_AT_RISK_ENTITIES
FROM snowflake.trust_center.findings
WHERE UPPER(STATE) = 'OPEN' AND TOTAL_AT_RISK_COUNT > 0
GROUP BY SEVERITY;

"We have critical findings that need attention. Let us drill in."

1.3 CIS 3.1 -- Network Policy (Critical)

[In Snowsight, click into CIS 3.1 finding. Show severity, at-risk entities, remediation SQL.]

"CIS 3.1 -- we don't have an account-level network policy. That means any IP address can attempt to connect. Trust Center flags this and gives you the exact SQL to fix it."

1.4 CIS 1.14/1.15 -- Admin Privileges (High)

SELECT SCANNER_NAME, SEVERITY, TOTAL_AT_RISK_COUNT
FROM snowflake.trust_center.findings
WHERE SCANNER_ID IN ('CIS_BENCHMARKS_CIS1_14','CIS_BENCHMARKS_CIS1_15',
                     'CIS_BENCHMARKS_CIS1_16','CIS_BENCHMARKS_CIS1_17')
  AND UPPER(STATE) = 'OPEN' AND TOTAL_AT_RISK_COUNT > 0
QUALIFY ROW_NUMBER() OVER
  (PARTITION BY SCANNER_ID ORDER BY END_TIMESTAMP DESC) = 1;

"41 tasks running with ACCOUNTADMIN. In the agentic world, this is exactly the over-privileged access that creates risk."

Act 2: PII Classification and Data Protection

Minutes 2:30 - 5:00

"One of the top concerns we hear is protecting sensitive data -- especially when agents can access it. Step one: know where it lives."

2.1 Show the HR Data

SELECT * FROM DEMO_DB.PUBLIC.HR_DATA LIMIT 5;

"Here's an HR table -- names, emails, ages. Let's ask Snowflake to automatically classify what's in it."

2.2 Run Auto-Classification

SELECT EXTRACT_SEMANTIC_CATEGORIES('DEMO_DB.PUBLIC.HR_DATA');

[Click JSON result to expand. Point out: email, name, age detected.]

"Snowflake identified EMAIL_ADDRESS as email, FNAME and LNAME as names, AGE as a personal identifier. No manual tagging needed."

2.3 Apply Classification Tags

CALL ASSOCIATE_SEMANTIC_CATEGORY_TAGS(
    'DEMO_DB.PUBLIC.HR_DATA',
    EXTRACT_SEMANTIC_CATEGORIES('DEMO_DB.PUBLIC.HR_DATA')
);

"Tags applied. Every column now has a semantic category and privacy classification. Foundation for protection policies."

2.4 Show Masking in Action

SELECT REPORT_ID, ANALYST_NAME, ANALYST_EMAIL, ANALYST_PHONE,
       TICKER, RECOMMENDATION, PRICE_TARGET, CONFIDENTIAL_NOTES
FROM RBAC_DEMO_DB.ANALYST_DATA.STOCK_ANALYST_DATA LIMIT 5;

"As admin, I see everything -- names, emails, price targets, confidential notes. Switch to a restricted role and masking policies redact the sensitive fields. Same table, same query, different results. Whether it's a human or an agent."

2.5 Connect to Trust Center

SELECT SCANNER_NAME, SEVERITY, TOTAL_AT_RISK_COUNT
FROM snowflake.trust_center.findings
WHERE SCANNER_ID = 'CIS_BENCHMARKS_CIS4_10'
  AND UPPER(STATE) = 'OPEN' AND TOTAL_AT_RISK_COUNT > 0 LIMIT 1;

"CIS 4.10 flags classified data without masking. Classification finds the data, Trust Center ensures it's protected."

Act 3: AI Security -- Enable Live

Minutes 5:00 - 7:30

"Now let's turn on agent security. Purpose-built controls for the agentic era."

3.1 Show AI Security is Disabled

SELECT ID, NAME, STATE FROM snowflake.trust_center.scanner_packages
WHERE ID = 'AI_SECURITY';

[Result: STATE = FALSE]

"AI Security is available but not yet enabled. Let's change that."

3.2 Enable AI Security -- The Live Moment

[Pause for effect before running this]

CALL snowflake.trust_center.set_configuration(
    'ENABLED', 'TRUE', 'AI_SECURITY', false);

"One command. That's all it takes."

3.3 Show What AI Security Checks

SELECT NAME, SHORT_DESCRIPTION FROM snowflake.trust_center.scanners
WHERE SCANNER_PACKAGE_ID = 'AI_SECURITY' ORDER BY NAME;

"Four scanners for real-world AI security:"

  • Cortex AI Guardrails -- prompt injection protection enabled?
  • Cortex Code PAT Usage -- PATs scoped with role restrictions and network policies?
  • Cortex Search Service Privileged Roles -- search services owned by admin?
  • Sensitive Data Accessed by Agent -- agents touching classified data?

"This is agent security -- built into the platform."

3.4 Run AI Security Scanners

CALL snowflake.trust_center.execute_scanner('AI_SECURITY');

SELECT SCANNER_NAME, SEVERITY, TOTAL_AT_RISK_COUNT,
       UPPER(STATE) AS STATE
FROM snowflake.trust_center.findings
WHERE SCANNER_PACKAGE_ID = 'AI_SECURITY'
ORDER BY END_TIMESTAMP DESC LIMIT 10;

"Scanners running. Findings appear alongside CIS and Security Essentials -- all in one place."

>> Transition: The final piece is threat detection.

Act 4: Threat Intelligence -- Detection Scanners

Minutes 7:30 - 10:00

"We've covered platform security, data protection, agent security. The final piece: real-time threat detection."

4.1 Enable Threat Intelligence

CALL snowflake.trust_center.set_configuration(
    'ENABLED', 'TRUE', 'THREAT_INTELLIGENCE', false);

"Threat Intelligence is now enabled."

4.2 Show Detection Scanners

SELECT NAME, SHORT_DESCRIPTION FROM snowflake.trust_center.scanners
WHERE SCANNER_PACKAGE_ID = 'THREAT_INTELLIGENCE' ORDER BY NAME;

"18 scanners across four categories -- not configuration checks, active threat detections."

Identity & Auth (6 scanners):

  • Login Protection -- logins from known malicious IP addresses
  • Dormant User Login -- inactive accounts suddenly waking up
  • Users with High Volume of Authentication Failures -- brute force attempts
  • Human User MFA Readiness -- migrate away from password-only sign-ins
  • Service User Passwordless Readiness -- legacy service accounts still using passwords
  • Password Sign-In Without MFA -- users bypassing MFA

Privilege Monitoring (2 scanners):

  • MANAGE GRANTS Privilege Monitoring -- who can grant access
  • Users with new Admin Privilege Grants -- new admin escalations

Anomaly Detection (3 scanners):

  • Users with unusual application sessions -- sessions from unusual apps
  • Users with Long-Running Queries -- suspicious long-running queries
  • Users with High Volume of Job Failures -- high job failure rates

Data & Config Protection (7 scanners):

  • Sensitive Parameter Protection -- data movement safeguards disabled
  • Share Exposure Monitoring -- new data share exposures
  • SCIM Token Creation Monitoring -- new SCIM token creations
  • Security Integration Monitoring -- security integration changes
  • Network Policy Configurations -- network policy changes
  • Authentication Policy Changes -- authentication policy modifications
  • Sensitive Policy Changes -- session and password policy changes

"From knowing what's misconfigured to knowing what's actually happening in your account."

4.3 Run and Show Full Picture

CALL snowflake.trust_center.execute_scanner('THREAT_INTELLIGENCE');

SELECT SCANNER_PACKAGE_NAME, SEVERITY,
       COUNT(*) AS FINDING_COUNT,
       SUM(TOTAL_AT_RISK_COUNT) AS TOTAL_AT_RISK
FROM snowflake.trust_center.findings
WHERE UPPER(STATE) = 'OPEN' AND TOTAL_AT_RISK_COUNT > 0
GROUP BY SCANNER_PACKAGE_NAME, SEVERITY
ORDER BY SCANNER_PACKAGE_NAME;

"CIS Benchmarks for compliance. Security Essentials for hygiene. AI Security for agent guardrails. Threat Intelligence for real-time detection. All four packages, every at-risk entity, one place. Proactive, enterprise-grade security for data and AI. Built in, not bolted on."
